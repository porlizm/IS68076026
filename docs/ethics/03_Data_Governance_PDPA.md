# แผนการจัดการข้อมูลและการปฏิบัติตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562

ส่วนที่เกี่ยวกับกฎหมายเป็นข้อเสนอของผู้วิจัยเพื่อให้อาจารย์ที่ปรึกษาและคณะกรรมการจริยธรรมพิจารณา ไม่ใช่ความเห็นทางกฎหมาย ส่วนมาตรการทางเทคนิคอธิบายสิ่งที่ระบบทำจริงและมีเทสต์รองรับ

## 1. บทบาท

| บทบาท | ผู้รับผิดชอบ |
|---|---|
| ผู้ควบคุมข้อมูลส่วนบุคคล | ผู้วิจัย ภายใต้การกำกับของอาจารย์ที่ปรึกษาและสถาบัน [กรอก: ยืนยันกับคณะว่าผู้ควบคุมคือผู้วิจัยหรือสถาบัน] |
| ผู้ประมวลผลข้อมูลส่วนบุคคล | Google (Workspace, Document AI, Gemini API), OpenAI, Anthropic |
| ผู้เข้าถึงข้อมูลระบุตัว | ผู้วิจัยคนเดียว ผู้วิจัยให้รหัสชุดคำตอบอ้างอิงเอง |

## 2. ฐานทางกฎหมายและหน้าที่

| ประเด็น | มาตรา | การปฏิบัติในโครงการ |
|---|---|---|
| ฐานในการประมวลผล | ม.19 ความยินยอม | ข้อคำถามบังคับในแบบฟอร์ม ระบบตรวจก่อนประมวลผล (`engine.validateIntake` คืน `consent_not_given`) ข้อความชัดเจน ถอนได้ง่ายเท่ากับให้ |
| การแจ้งรายละเอียด | ม.23 | เอกสารชี้แจงผู้เข้าร่วมและข้อความหัวแบบฟอร์ม ระบุวัตถุประสงค์ ข้อมูลที่เก็บ ระยะเก็บ ผู้รับ สิทธิ และช่องทางติดต่อ |
| การส่งไปต่างประเทศ | ม.28 | ผู้ให้บริการอาจประมวลผลนอกประเทศ ใช้ความยินยอมหลังแจ้งว่าปลายทางอาจมีมาตรฐานไม่เท่ากัน (หนังสือยินยอมข้อ 2) ส่งเฉพาะข้อความหลังปิดบังให้โมเดล |
| ข้อมูลอ่อนไหว | ม.26 | เรซูเมอาจมีข้อมูลอ่อนไหวที่ผู้เข้าร่วมใส่เอง เช่น ศาสนา สุขภาพ แจ้งในเอกสารชี้แจงให้ลบก่อนส่ง [กรอก: ให้คณะกรรมการพิจารณา] |
| แจ้งเหตุละเมิด | ม.37 (4) | แจ้งอาจารย์และคณะกรรมการทันที ประเมินหน้าที่แจ้งสำนักงานภายใน 72 ชั่วโมงนับแต่ทราบเหตุ |
| สิทธิของเจ้าของข้อมูล | ม.30 ถึง 36 | ขอเข้าถึง แก้ไข ลบ ถอนความยินยอม ทางอีเมลที่ระบุในรายงานทุกฉบับ (`config/project.json` คีย์ `deletion_contact`) |

## 3. มาตรการทางเทคนิค

| มาตรการ | ที่ทำในระบบ |
|---|---|
| ปิดบังข้อมูล 4 รูปแบบก่อนส่งโมเดล | `engine.maskPII` แทนด้วย [EMAIL] [URL] [PHONE] [ID] และนับจำนวนลง `ocr_results.pii_masked_count` |
| อีเมลจากการยืนยันตัวตน Google เท่านั้น | Forms ตั้ง "Collect verified emails" ระบบใช้คอลัมน์ Email Address |
| ส่งอีเมลทีละฉบับต่อคน | ส่งหนึ่งฉบับต่องาน กันส่งซ้ำด้วย report_hash |
| รายงานไม่มีข้อผิดพลาดทางเทคนิค | ข้อผิดพลาดส่งให้ผู้วิจัยเท่านั้น |
| จำกัดสิทธิ์ | ไฟล์ทั้งหมดอยู่ในบัญชีผู้วิจัย แชร์ให้บัญชีบริการเฉพาะโฟลเดอร์ที่จำเป็น ไม่เปิดสาธารณะ |
| audit_log ไม่เก็บอีเมล | บันทึกเหตุการณ์ด้วย run_id และ response_id |
| ค่าลับไม่เข้า git | `.env` และ `private/` อยู่ใน `.gitignore` |
| ข้อความหลังปิดบังเก็บแยก | โฟลเดอร์ส่วนตัวของ `DRIVE_MASKED_TEXT_FOLDER_ID` ลบตามรอบ 90 วัน |
| ที่เก็บคำตัดสินของผู้ตรวจ (cache) | เก็บเฉพาะรหัสแฮชของคู่ข้อความกับข้อกำหนด (รวมรหัสรุ่นโมเดลและ prompt) กับคำตัดสินและเวลา ไม่เก็บตัวข้อความและไม่ผูกกับตัวบุคคล ปิดใช้ตอนวัดความคงที่ของผลและลบทั้งหมดเมื่อสิ้นสุดโครงการ |

## 4. วงจรชีวิตข้อมูลและการลบ

| ข้อมูล | ที่เก็บ | ลบเมื่อ | วิธีลบและหลักฐาน |
|---|---|---|---|
| PDF ต้นฉบับ | Drive โฟลเดอร์ของแบบฟอร์ม | 90 วันหลังส่งผล | ลบไฟล์และล้างถังขยะ บันทึก audit_log event `retention_deleted` |
| ข้อความหลังปิดบัง | Drive โฟลเดอร์ masked_text | 90 วัน | เหมือนข้างบน |
| รายงาน PDF | Drive โฟลเดอร์รายงาน | 90 วัน | เหมือนข้างบน |
| แถวที่ระบุตัว (runs.email, runs.file_id, deliveries.email_to, form_responses) | Google Sheets | 90 วัน | ลบแถวหรือล้างค่า เหลือ run_id เพื่อการวิเคราะห์ |
| ประวัติ execution ของ n8n | เครื่องที่รัน n8n | 90 วัน | ตั้ง `EXECUTIONS_DATA_MAX_AGE=2160` ใน env |
| ไฟล์งานให้รหัสและ export | `private/` (ไม่เข้า git) | หลังวิเคราะห์เสร็จ | ลบโฟลเดอร์และบันทึกวันที่ |
| ที่เก็บคำตัดสินของผู้ตรวจ | ข้อมูลคงที่ของ workflow ใน n8n | สิ้นสุดโครงการ | ล้างค่าและบันทึกวันที่ |
| ข้อมูลในระบบผู้ให้บริการ | ตามนโยบายผู้ให้บริการ | ตามนโยบาย | ดู `04_Data_Flow_Overseas` |

ต้องมีขั้นตอนลบรายสัปดาห์ และทดลองลบกับข้อมูลนำร่องก่อนเก็บกลุ่มหลัก

## 5. การใช้ Demo

โปรแกรมสาธิตใช้เรซูเมของผู้วิจัยเองหรือเรซูเมสังเคราะห์เท่านั้น ไม่ใช้เรซูเมของผู้เข้าร่วมวิจัย จนกว่าจะได้หนังสือรับรองจริยธรรมและผู้เข้าร่วมยินยอมให้ใช้ในการสาธิต

## 6. ข้อจำกัดที่ต้องเปิดเผย

- ข้อมูลระบุตัวที่ไม่ตรงรูปแบบ (ชื่อ ที่อยู่ ชื่อบริษัท ชื่อสถาบัน) ยังอาจอยู่ในข้อความที่ส่งโมเดล
- ไฟล์ที่ส่งให้บริการอ่านข้อความยังไม่ผ่านการปิดบัง เพราะการปิดบังเกิดหลังได้ข้อความ
- ถ้าคณะกรรมการกำหนดให้ปิดบังเพิ่ม ต้องปรับรูปแบบการปิดบังและรายงานผลกระทบต่อการตัดสินข้อกำหนด แล้วรันเทสต์ใหม่
